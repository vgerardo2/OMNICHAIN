# Three-minute demo outline

This is a rehearsal script, not a claim that a timed presentation has been completed.
Use **Scripted demo**; no API key or internet connection is required for its inference.

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:25 | Authorized invoice task | The assistant should summarize the invoice for an approved recipient. The invoice note tries to redirect it into reading restricted data and sending it elsewhere. |
| 0:25–0:55 | Run attack, then Evidence | These are authored proposals through real mock-policy checks. Open an event block to inspect the recorded request and result. No real data or message is involved. |
| 0:55–1:30 | Compare controls | The filter misses a reworded attack and blocks one ordinary task. Approved recipients can stop delivery while still allowing a restricted read. Task-only permissions meet this small suite's requirements. |
| 1:30–1:55 | Select a defense | Review the counts, enter a reason, and select an eligible defense. Weights record preferences; they do not override required checks or rank unknown cost and maintenance. |
| 1:55–2:25 | Validate selection | Five separate cases check the exact settings, task output, evidence, and restoration of mock state. PASS applies only to this defined suite. |
| 2:25–3:00 | Evidence verification and export | Test changed or missing records on copies. Export the linked assessment. Explain that hashes do not prevent a privileged full rewrite and live AI has not been provider-tested. |

Before presenting, run the tests and rehearse this path on the actual presentation
device. If the app reports incomplete evidence or a failed check, show that result.
Keep scripted and live-model claims separate. Confirm any event-specific deadline
or eligibility directly with the host; this script makes no submission claim.
